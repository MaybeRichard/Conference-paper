# M2A Lexical Retrieval Implementation Plan

> For agentic workers: use superpowers:executing-plans. Execute in the isolated M2A branch, do not merge M1 or alter the user's working checkout.

**Goal:** Deliver real title/abstract retrieval plus missing-abstract protection and an auditable candidate report.
**Architecture:** CorpusAdapter → immutable SQLite/FTS5 index → bounded multi-channel retrieval → report; public ResearchAgent API → CLI. Existing orchestrator and all research Gates unchanged.
**Tech Stack:** Existing Python 3.11+, sqlite3, pathlib, hashlib, json, filelock, Pydantic, pytest. No embedding/network/model dependency.
**Spec:** `docs/superpowers/specs/2026-09-06-design-v1.1-m2a.md`.

## Global constraints

- Preserve `corpus/`, `scripts/`, data notices/manifests and the existing Node corpus test.
- Do not overwrite existing indexes, reports, user modifications or persisted M1 objects.
- Report `scope_status=unreviewed`; keyword matches are not verified 2D generation eligibility.
- Missing-abstract queue is not abstract enrichment.
- Standalone search is not a completed S2 stage or G2 approval.
