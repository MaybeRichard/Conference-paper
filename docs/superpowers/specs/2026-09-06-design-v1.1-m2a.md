# Design v1.1 — first executable retrieval slice (M2A)

Status: implementation of the user's approved first retrieval batch; not a claim that all v1.1 research capabilities are complete.
Base: M1 `3c712fb722ca9fc2268a88eebd9f6a14e8a898f1`.
Branch: `feat/research-agent-m2a-lexical`, based on the unmerged M1 branch. Do not change or merge PR #1.

## Delivered boundary

An offline, snapshot-pinned exploratory retrieval tool: build/verify/status a SQLite FTS5 index; search title and abstract separately and jointly; retain title-matching records without abstracts; export an auditable candidate report and metadata-enrichment queue. No network, LLM, embedding, automatic abstract supplementation, PDF reading, semantic eligibility verdict, novelty verdict or G2 selection is claimed.

The existing Workspace and Gate contracts remain unchanged. `run` still stops at S2; manual `search` is a standalone exploration command, not completion of the S2/S3 workflow. It does not create or approve a research Gate. This distinction must be visible in CLI results and reports.

## Index contract

- CorpusAdapter verifies the fixed snapshot, all referenced manifests and shard bytes. Index publication occurs only after the complete verified stream is consumed.
- Extend the adapter with a backwards-compatible located-record iterator: unchanged record, shard path/hash and 1-based nonempty record number. No writes to corpus.
- Store one index row per source record. Do not merge similar titles or DOI variants automatically; expose normalized-title duplicate groups as hints.
- Preserve provenance, original title, source identifiers and missing/placeholder-abstract status. Index only source title/abstract, never generated interpretations.
- Derived files reside below ignored `indexes/`; build into a fresh staging directory, then atomically publish a completed immutable index directory. No overwrite, no force repair of corrupt existing index.
- Manifest includes snapshot identity/hash, index/profile identity, counts, field coverage, SQLite version, database SHA-256, build time and record-normalization version.
- Read-only search checks index checksum/counts. `index verify` also revalidates source corpus. File integrity is not publisher authenticity or protection from an attacker replacing both manifest and DB.
- Static symlinks and traversal are rejected; concurrent hostile filesystem mutation is outside the existing single-user trusted-checkout threat model.

## Search contract

- Plain-text query only; user input is never SQL or raw FTS syntax. Bound parameters and escaped FTS literals.
- A small versioned Chinese/English medical-generation glossary expands known concepts. Original input, expanded groups and warnings are saved. Unrecognized Chinese modifiers cause an explicit input error rather than silent scope broadening. English generic terms remain literal requirements.
- `二维` is a screening intent, NOT an FTS requirement: mentioning CT/MRI/3D is not an automatic exclusion. Results carry independent lexical flags and `scope_status=unreviewed`.
- Title, abstract and joint-field BM25 lists are fused by deterministic reciprocal rank fusion with k=60. BM25 scores are not summed across unlike indexes. Per-channel ranks are preserved.
- A separate missing-abstract/title lane reserves up to 20% of the final requested slots (minimum one when available). Record the selection reason; reserve only query-matching records.
- Broad medical queries may relax the medical-word clause for titles from MICCAI/ISBI, explicitly recording that venue is a retrieval prior, not proof of relevance.
- Conference/year filters apply before channel truncation. Save per-channel match counts, retrieval cap, truncation flags and result coverage; no claims of exhaustive literature coverage or Recall@K.
- Enrichment queue contains missing-abstract records from the bounded retrieved union, not all missing abstracts in the corpus. Membership and selection status are explicit.

## Reports and safety

Reports under `indexes/reports/<random-run-id>/`: search.json, candidates.jsonl, missing_abstract_queue.jsonl, report.md, return_bundle.zip. No corpus/PDF/Workspace/secrets are packaged; no full abstracts in return_bundle. Text and links are escaped/validated for Markdown. Output is never an instruction source. Failed searches do not produce completed reports.

CLI: `index build [--snapshot-id]`; `index verify [--index-id]`; `index status [--index-id]`; `search --query TEXT [--index-id] [--limit 50] [--per-channel 500] [--conference NAME] [--year-from N] [--year-to N] [--report]`.
Public API owns dispatch; CLI stays thin. Success emits one JSON object and exit 0, input errors 2, conflicting publication 3, integrity/path errors 4, unavailable index/FTS capability 5, lock contention 6. No new third-party dependency.

## Deferred v1.1 changes

Existing persisted objects are not silently migrated in M2A. Core two-dimensional research constraints are unchanged.

Automated success is not proof of research relevance; provide actual candidate output for the user's first useful review.
