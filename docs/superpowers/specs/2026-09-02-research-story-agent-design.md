## 1. 目标、已批准决策与范围

### 1.1 系统定位

以版本化论文元数据语料为起点，按照研究者的工作方式，将一个宽泛方向逐步转化为有证据、有方法机制、有新颖性边界、可实验验证的研究故事。

```text
研究方向 → 检索与初筛 → 核心全文精读 → 领域认知
→ 痛点与研究机会 → 本领域及跨领域机制探索
→ 候选 Idea → 撞车检查与对抗式审稿
→ 用户选择 → 方法规范、实验蓝图与论文骨架
```

系统不是自由多 Agent 群聊，不是一次性摘要 RAG，也不承诺自动产生一定录用的论文。主要价值是帮助研究者决定查什么、读什么、相信什么、怀疑什么、做哪个实验，以及何时放弃或修订故事。

用户的“球—网—漏洞”比喻对应：

| 对象 | 含义 |
|---|---|
| `PainPoint` | 有范围、有证据的困难、失败现象或约束，即球 |
| `SolutionMechanism` | 解决问题的方法机制，即网 |
| `Coverage` | 机制在什么条件下已覆盖哪些能力 |
| `ResidualGap` | 未解决、未评价或证据冲突的条件，即网的漏洞 |
| `TransferableMechanism` | 可从其他任务或领域借鉴的不变原理 |
| `ResearchStory` | 问题、洞察、方法、证据计划和风险组成的可检验故事 |

### 1.2 已批准决策记录

| 编号 | 项目 | 决定 |
|---|---|---|
| D01 | 全文策略 | 混合精读：摘要负责广度，精选全文负责深度；获取失败时允许用户补充 |
| D02 | 搜索来源 | 本地语料优先，主动补充外部论文、预印本、官方页面与代码线索 |

| D06 | 维度 | 原生二维及独立 CT/MRI 等二维切片；排除 2.5D 和 3D |
| D07 | 产品形态 | Python 核心 + 稳定 Python API/CLI + 仓库内对话式 Skill |

| D09 | 认知治理 | 证据、综合推断、研究假设、迁移和风险分离 |

| D12 | 数据资源 | L1/L2/L3 分层呈现，不只生成依赖理想数据的故事 |

### 1.3 二维与任务边界

纳入 X-ray、病理 patch、眼底、皮肤镜、超声单帧、内镜等原生二维影像，以及独立 CT/MRI/PET 切片。模型输入、训练单位和主要评价必须能在单张二维样本上成立。

排除三维网络、3D latent diffusion、相邻切片联合输入、2.5D、体数据生成以及以跨切片一致性、体积或三维形态为核心的贡献。CT/MRI 数据来源于体数据本身不是排除理由；患者级划分仍必须保留。

重建、去噪、超分辨率、分割和配准不作为本课题主综述任务，但可提供机制或评价启发。以生成合成数据改善下游分割为主要研究对象的论文仍可纳入；仅用扩散模型执行分割的论文不纳入主线。

Flow matching、consistency 等相邻生成路线可以作为比较或迁移来源，不因术语相近而静默扩大“扩散生成”的主研究边界。范围不清的论文保留待核验状态。

### 1.4 数据与计算资源

- L1：公开数据及已有标注经常规预处理即可验证。
- L2：公开数据需要派生标注、配对构造、伪标签、长尾划分或有限补标。
- L3：需要私有临床数据、专家标注、特殊设备或医院合作。

数据集和评价资源分别标级：公开训练数据配合专家盲评可能是数据 L1、评价资源 L3，不能全部标为无门槛。每个故事报告最低资源等级、理想等级、额外工作量、质量控制和替代验证。

“训练算力不设硬上限”不等于 Agent 无限搜索和调用模型。研究算力约束与运行预算分开建模。

### 1.5 非目标

首版不做 Web、多用户、微服务、全量 PDF 下载、完整图数据库、自动运行外部代码、自动训练、自动投稿或伪造实验结果。实验回流接口用于记录研究者实际提供的结果，不意味着系统执行了实验。

## 2. 设计一：系统边界与仓库分层

### 2.1 当前仓库事实与保护范围

基线提交为 `17a6fdfce7d6da8cda2462bb40ca6a204df242c4`。该版本根 README 登记 13 个会议、113,989 条记录、86 个 release、200 个数据文件，当前快照为 `snapshot_a6ef56370e3258f5`。这些是仓库声明的记录规模，不应未经核验改写为跨来源完全去重的独立论文数量。

依据文件：仓库根 `README.md`、`corpus/registry.json`、`DATASET_MANIFEST.json`、`corpus/README.md` 和 `DATA_NOTICE.md`。正式索引构建必须重新校验指定快照和文件哈希，不能仅信任 README 数字。

保留现有文件路径和测试入口。尤其不在添加 Agent 的同时迁移或重写已有完整性测试。数据导入器维护 corpus；科研运行时只读 corpus。

### 2.2 五类资产

| 资产 | 权威来源 | 更新方式 |
|---|---|---|
| 原始元数据 | `corpus/` 及其 manifest | 新 release + 新 snapshot |
| 外部材料 | 来源地址、文档版本和内容哈希 | 增量获取，来源许可控制 |
| 检索索引 | 由元数据重建 | 按索引 profile 重建 |
| 研究过程 | 版本化 Artifact 和事件 | 新版本，不静默覆盖 |
| 最终研究产物 | Story Package 及其依赖 | 随证据、用户决策修订 |

语料库保存“论文是什么”；研究工作区保存“系统和研究者如何理解这些论文”。向量库不能成为唯一研究记忆。

### 2.3 推荐布局

```text
Conference-paper/
├── corpus/                         # 原始语料，研究运行时只读
├── scripts/                        # 现有采集与导入器
├── DATASET_MANIFEST.json
├── DATA_NOTICE.md
├── research_agent/
│   ├── core/                       # 状态、Gate、Task、Artifact、事件
│   ├── schemas/                    # 研究产物契约
│   ├── retrieval/                  # 召回、筛选、去重、覆盖
│   ├── fulltext/                   # 解析、定位、身份核验
│   ├── reading/                    # 忠实抽取、批判阅读、核验
│   ├── synthesis/                  # 领域地图、方法与机会
│   ├── ideation/                   # 迁移、Idea、故事
│   ├── review/                     # 撞车、审稿、实验审计
│   ├── adapters/                   # 来源、模型、存储接口
│   ├── api.py
│   └── cli.py
├── domains/medical_diffusion_2d/
├── skills/research_story_agent/
├── config/
├── indexes/                        # 可重建，默认不提交
├── workspaces/                     # 私有研究状态，默认不提交

```

该布局描述职责，不要求首日创建全部空目录或空类。先实现实际纵向切片需要的模块。

### 2.4 通用与领域边界

内核理解论文、证据、问题、机制、局限、机会、Idea、实验和故事；领域配置提供模态分类、二维判断、生成任务范围、术语、指标、医学约束和投稿取向。

领域配置包括 `domain.yaml`、`taxonomy.yaml`、`query_expansions.yaml`、`exclusion_rules.yaml`、`mechanism_dictionary.yaml`、`evaluation_rubric.yaml`、`miccai_reviewer.yaml`、`datasets.yaml` 及领域提示模板。

MICCAI 评价权重是本项目的启发式 rubric，不是官方审稿政策或录用概率。届时引用官方政策或数据许可条款，需要独立核对来源与日期。

## 3. 设计二：研究产物、证据模型与可追溯性

### 3.1 身份与版本

每个正式 Artifact 必須包含稳定 `artifact_id`、`schema_version`、对象版本、内容哈希、创建时间、生产任务、依赖列表、状态以及可选 `supersedes`。

论文区分 canonical paper、来源变体和全文版本。Evidence 绑定具体 `document_version_id` 与内容哈希，而不是只绑定论文标题。

Core Schema 至少包括：ResearchBrief、SearchPlan、CandidatePaperSet、ScreeningDecision、CorePaperSet、Document、PaperEvidenceCard、Claim、Evidence、MethodFamily、PainPoint、ResidualGap、ResearchOpportunity、TransferCard、IdeaProposal、NoveltyAssessment、ReviewerCritique、ExperimentBlueprint、ResearchStory、DecisionRecord。

### 3.2 原子 Claim

Claim 的必要字段：

| 字段 | 约束 |
|---|---|
| `statement` | 一条可独立判断的陈述，复合主张拆开 |
| `epistemic_status` | FACT / SYNTHESIS / HYPOTHESIS / TRANSFER / RISK |
| `origin` | 作者陈述、论文实验、官方元数据、用户判断或 Agent 推断 |
| `scope` | 任务、模态、维度、数据条件、时间窗、适用范围 |
| `supporting_evidence` | 有类型的 Evidence 引用 |
| `counter_evidence` | 反证、限定或尚未完成的反证搜索 |
| `confidence` | 来源质量、直接性、一致性、覆盖及其理由 |
| `review_status` | 结构、证据、人工审阅状态 |

不得把“质量差、速度慢、病灶不真实、临床价值不足”作为一条 Claim。置信度未经校准时采用有理由的等级，不能把模型自报分数当作概率。

### 3.3 认知状态的具体语义

FACT 表示在限定范围内可以定位核验的陈述，不表示一切作者断言都是真的。“作者声称改善临床真实性”可以是来源事实；“方法已被证明临床可信”必须检查相应实验是否足以支持。

SYNTHESIS 是单篇或多篇证据与明确推理形成的综合判断。多来源数量不是充分性证明，来源之间的独立性、偏差和覆盖范围同样重要。

HYPOTHESIS 必须带机制解释、适用边界、预测、竞争性解释、反证条件和最低验证实验。

TRANSFER 必须带源问题、源机制、不变原理、目标对应、领域差异、必要改造及失败风险。它表示待验证的迁移设计，不能因源论文有效就视为目标领域事实。

RISK 是可能使方案失效的条件。数据、指标、临床主张、方法、新颖性、统计、计算、许可和隐私风险均须显式保存。

### 3.4 Evidence 与支持关系

Evidence 记录来源类型、论文/文档版本、页码或 HTML anchor、章节、段落或 block ID、图表 ID、短片段或转述、内容哈希、获取时间和解析 profile。

支持关系统一为：`supports`、`partially_supports`、`qualifies`、`contradicts`、`fails_to_test`、`context_only`。反例同样使用这些关系，不维护第二套冲突枚举。

证据强度按所支撑的具体 Claim 判断，不设“正文一律强于代码”等不分任务的固定等级。例如实现细节可能以固定 commit 的代码为直接来源，效果判断则需要实验协议和结果。

### 3.5 局限的四种类型

- `author_stated_limitation`：作者明确承认。
- `observed_failure`：实验在指定条件下观察到失败。
- `evaluation_omission`：对读取过且范围明确的文档未见对应评价。
- `inferred_mechanistic_limitation`：系统依据机制推断，仍需验证。

缺少全文、附录或图表时，不能从“当前解析文本没出现”直接推出“论文没有评价”。应使用 `unknown` 或“在已访问材料中未见”，并记录缺失材料。

### 3.6 硬性门控与能力边界

代码可强制检查：FACT 有来源引用、Evidence ID 存在、文档版本匹配、Locator 可解析、必填字段完整、Idea 有证伪方案、范围不冲突。

“原文是否真正支持结论”“指标是否测到了所主张能力”属于语义核验，需要模型与抽样人工复查。Schema 通过不能被解释为科学结论被机械证明。

禁止把未评价写成失败；禁止把搜索未命中写成无人研究；禁止把预计结果写成实验结果。

### 3.7 生命周期与格式

正式产物可经历 `draft → schema_validated → evidence_checked → machine_reviewed`，只有四个 Gate 所确认的对象标记对应用户批准。无需让用户逐张批准所有论文卡。

JSONL 保存批量记录和事件；YAML/JSON 保存配置与结构化产物；Markdown 为可重新生成的阅读视图；SQLite/向量库仅加速查询。旧版本通过 `superseded/rejected/stale` 保留，不静默删除。

## 4. 设计三：工作流、状态机与四个确认节点

### 4.1 流程和阶段完成条件

| 阶段 | 工作与输出 | 最低完成条件 |
|---|---|---|
| S0 | 创建 Workspace，绑定 corpus snapshot | 快照、策略、身份明确 |
| S1 | 形成 ResearchBrief | 范围、目标、时间窗和排除项明确 |
| G1 | 用户确认研究边界 | 记录具体 Brief 版本的明确决定 |
| S2 | SearchPlan、多路检索、外部补充 | 查询和覆盖审计有记录 |
| S3 | 初筛、去重、聚类、核心集合建议 | 每项选择/排除有理由 |
| G2 | 用户确认核心论文 | 确认集合版本及精读角色 |
| S4 | 全文获取、身份与解析 | 每篇均有获取、质量与缺失状态 |
| S5 | 两遍精读、Evidence 核验 | 强 Claim 来源可定位，推断分离 |
| S6 | 领域地图、覆盖、Gap 与 prior-art 边界 | 机会有支持、反证或未完成项说明 |
| G3 | 用户选择研究机会 | 选择 1–3 个方向或要求补证 |
| S7 | 本领域与跨领域机制检索 | 机制依据、迁移差异和风险明确 |
| S8 | Idea Seeds 聚类并形成候选 | 假设、方法、证伪、简单基线齐全 |
| S9 | 最新工作撞车与有限修订 | Claim-level 对比和检索时间可追溯 |
| S10 | 对抗审稿、实验审计 | 主要攻击与实验对应，风险可见 |
| G4 | 主故事与备选选择 | 用户选择及切换条件有记录 |
| S11 | Story Package | 方法、实验、贡献边界与论文骨架一致 |

前后两次撞车核查分别落实在 S6 的已有工作边界与 S9 的候选专项核查，不能只保留后一次。

### 4.2 Gate 语义

批准绑定 `gate_id + artifact_version + content_hash`，不是泛化的“以后都同意”。角色不得自动批准。新论文补充或范围改变若影响已批准核心选择，相应 Gate 失效并要求针对变更重新决定，不能重问全部已知约束。

普通查询、解析重试和不改变研究方向的补证无需逐次审批。核心名单中的新增全文精读对象应作为明确增量处理；G3 所批准机会可以授权其范围内的迁移/最近工作补充阅读，超出范围才重新确认。

### 4.3 状态与回退

阶段状态：`not_started/running/completed/waiting_for_user/blocked/needs_revision/superseded/failed`。唯一推进者为 Orchestrator。

| 触发 | 回退 |
|---|---|
| 关键路线未覆盖 | S2 |
| 关键全文缺失导致判断不能成立 | G2 补充，不静默换成方便下载的弱相关文献 |
| 证据冲突、解析错配 | S4/S5 |
| 痛点依据不足 | S2/S5/S6 |
| 迁移牵强 | S7 |
| 高度撞车 | S7/S8 |
| 实验不区分解释 | S8/S10 |
| 数据不可得 | G3 或收缩主张 |

每次回退记录原因、目标、新信息要求、触发证据和已使用预算。

默认软预算：检索扩展 3 轮、核心集合修订 2 轮、每篇全文尝试 3 类来源、Gap 补证 2 轮、每个 Idea 撞车修订 2 轮、审稿后结构修订 2 轮。预算到达后保留部分产物并说明阻塞，不自动伪装完成。

### 4.4 Workspace 最小状态

`workspace.yaml` 保存 ID、题目、领域、目标会议、固定快照、工作流版本、有效配置版本、当前阶段、Gate 和状态。`events.jsonl` 追加任务和决策事件。各研究结论置于版本化 Artifact，而非随意嵌入状态文件。

变更按依赖图传播 `stale`。下游若使用旧证据或被替换的机会，必须显式标记；保留旧结果用于审计，但不当作当前结果。

## 5. 设计四：混合检索、初筛与覆盖控制

### 5.1 索引与事实源

针对固定 snapshot 构建 `indexes/<snapshot-id>/<profile-id>/`，包括 `catalog.sqlite`、标准化文档视图、向量索引和 `index_manifest.yaml`。

Manifest 记录 snapshot、Schema、文档数、源哈希、文本清洗 profile、FTS 参数、embedding 模型及修订、维度、距离度量和构建时间。基础检索文本使用原始标题与摘要，不混入未验证的模型总结。

首版使用 SQLite 元数据与 FTS5，以及一个本地向量实现。具体依赖、版本和许可证在实施计划中核对、锁定；设计阶段不把可替换 Adapter 当作已经集成的服务。

### 5.2 多查询族

查询族包括 `broad_landscape/task_specific/modality_specific/problem_specific/mechanism_specific/evaluation_specific/frontier/counterexample/transfer_bridge`。

保留用户中文概念、英文规范术语、同义词、缩写、正负词、元数据过滤、生成来源和查询版本。痛点导向查询不能用来替代中性全景查询，否则会只召回支持预设故事的文献。

时间窗在 G1 写成绝对日期；默认近期窗口与允许纳入的历史奠基论文分开。不能把当前年份之前“约五年”留成不可复现的模糊条件。

### 5.3 召回与融合

独立执行标题 BM25、摘要 BM25、标题摘要语义召回，以及按需的已知论文/作者/引用扩展。

首版优先确定性排名融合；记录每路排名和融合参数。不得直接相加量纲不同的原始 BM25 与余弦分数而不归一化。影响力只作同类代表性弱信号，不代替相关性；新论文单独保留前沿通道。

### 5.4 范围筛选与低置信处理

二维标签：`include_2d/exclude_2_5d/exclude_3d/mixed/ambiguous`，带判断依据和置信理由。出现 CT、MRI、volume 或 3D 词不直接触发排除。

主线角色：`primary_target/supporting_evidence/transferable_mechanism/out_of_scope`。排除日志保留具体理由；模糊项由页面或全文复核。二次审查优先覆盖高排名被排除、没有摘要、维度混合、最近竞争者和标签冲突等风险项。

ScreeningDecision 分开回答：符合范围吗、主题相关吗、值得精读吗。相似论文可能相关却不必全部精读；评价论文可能语义排名不高却很重要。

### 5.5 去重与外部材料

优先 DOI、官方 ID、官方 URL，再以规范化标题、作者、年份提出候选合并。标题相似不是自动合并证据；会议版、预印本和扩展论文保留版本关系及可能差异。

主 corpus 不被外部搜索直接写入。外部元数据进入 Workspace，记录发表状态、首次公开日期、检索时间、元数据来源、全文来源和验证状态。预印本可参与撞车判断，但不能不加区别地当作正式同行评审证据。

### 5.6 核心集合和覆盖

运行参考规模：原始候选 300–800、摘要筛选 100–200、报告候选 50–100、核心全文 15–30。它们是调研预算与目标区间，不是必须填满的输出配额。

核心集合兼顾奠基、主流机制、最新工作、最近竞争者、评价/Benchmark、反例、数据任务和迁移桥接；通过角色、方法簇、时间和模态多样性选择，不只取 Top-K。

覆盖报告对任务×模态、年份、方法、评价、反例和前沿分别记录覆盖。空白仅表示当前检索不足，需补搜才可讨论文献稀疏性。

停止依据是主要路线覆盖、近期检查、聚类稳定、边际高价值新增减少、盲点已补搜或明确，以及预算。不能以“有 100 篇”证明完成。

### 5.7 检索产物与失败

输出 SearchPlan、queries、local/external hits、canonical papers、screening/exclusion decisions、ambiguous scope、clusters、coverage report、candidate papers 和面向用户的 Markdown。

语义索引失败可降级关键词检索；外部检索失败时保留覆盖警告，后续不得给低撞车风险结论；缺摘要论文不可自动当作无关。更新模型必须创建新索引 profile。

## 6. 设计五：全文获取、精读与证据抽取

### 6.1 获取范围和来源

只处理核心论文、关键迁移论文与危险最近工作。参考总量约 25–50 篇独立论文，集合有重叠时去重；实际数量取决于覆盖与证据需要。

Resolver 优先寻找官方开放全文、OpenReview、官方 proceedings、作者 arXiv/项目页，再接受用户上传。公开可访问不等于允许再次分发；访问、缓存、模型处理和导出分别遵守来源条款与用户授权。不绕过付费墙、登录、验证码或访问控制。

### 6.2 身份与版本

下载后核验标题、作者、DOI、文档类型和版本。结果为 `verified/probable/ambiguous/mismatch`；只有核验通过版本进入正式证据链。

主论文、补充材料、附录、作者回复和项目页面分别标识。正式版可作为主读版本，但不同版本的新增实验不得混写为同一版本证据。

### 6.3 统一 Document Model

```text
papers/<canonical-paper-id>/
├── paper.yaml
├── sources/       # 来源清单、原文、版本及哈希
├── parsed/        # document、sections、blocks、tables、figures、references
├── reading/       # faithful extraction、critical analysis、evidence、paper card
└── quality/       # identity、parse、evidence 报告
```

文本块保存页序、印刷页码（可得时）、章节、block ID、bounding box、类型和内容哈希。HTML 保存 anchor/DOM 定位及段落哈希。页码缺失不得编造。

正文、参考文献和引用他人的内容要区分，避免把 Related Work 的实验当成本论文结果。

### 6.4 图表与解析质量

默认提取图表标题、位置及可靠正文；关键 Claim 依赖图表时必须核验相应页面或图表图像，记录表头、单位、指标方向、组别、数值及不确定性。仅凭图注不推断曲线或表格结论。

复杂布局可要求用户核验，不能为自动化率虚构数值。OCR 仅在没有可用文本层或其他版本时受控使用，低置信输出必须标记。

ParseQualityReport 记录身份、页数覆盖、章节识别、阅读顺序、乱码、遗漏图表和整体质量 `high/usable/partial/failed`。示例结构不等于每项分数已校准。

### 6.5 阅读与核验

第一遍忠实抽取：问题、作者动机、方法、输入输出、条件、训练与推理、数据划分、基线、指标、结果、消融、作者局限和资源可得性。

第二遍批判阅读：主张支持度、额外数据/参数/监督的替代解释、缺失评价、公平性、域外验证、病灶/解剖指标、临床主张和潜在失败。

Evidence Checker 使用独立上下文查看 Claim 与原文，不继承作者或 Idea Agent 的辩护。输出支持、部分支持、限定、矛盾、未测试或上下文关系。

没有发现局限也是允许结果。不得要求每篇论文必须“造出一个缺陷”；可记录未发现、尚未访问或待核验。

### 6.6 论文卡与状态

PaperEvidenceCard 包括身份、问题、方法与假设、数据与协议、基线、指标、实验与消融、作者主张、支持不足主张、四类局限、可复现性、可迁移机制和 Evidence IDs。

全文状态独立保存 `unresolved/source_found/downloaded/identity_verified/parsed/parse_validated/deep_read/evidence_checked`，异常为 `access_failed/identity_mismatch/parse_partial/parse_failed/abstract_only/user_upload_required`。

摘要级材料只能支撑摘要中明示的有限陈述，不能支撑详细方法或“全文未评价”结论。全文缺失的重要竞争者留在报告中，不因下载失败从新颖性风险中消失。

### 6.7 缓存与矛盾

解析缓存按文档哈希+parser profile；阅读缓存按文档版本+Schema+Prompt+模型+领域配置。Workspace 绑定使用时的固定版本。

矛盾分析先检查数据、模态、分辨率、模型、指标、版本和条件是否可比。不兼容实验不得强行排名，不同名字的同一机制应归一化。

## 7. 设计六：领域认知、痛点图谱与研究机会

### 7.1 三个集合分工

Landscape Set 用于任务与路线分布；Evidence Set 用于深层机制与局限；External Frontier Set 用于最新边界。核心精读集是目的性选择，不是随机样本，不能据其比例声称“全领域多数方法失败”。

四遍流程：描述有什么 → 比较解决了什么 → 分析为何还有问题 → 筛选值得研究的机会。

### 7.2 领域地图与方法家族

分类轴包括任务、模态、条件、生成空间、机制和评价。论文允许多标签。

MethodFamily 记录底层原理、典型实现、目标痛点、假设、已验证与未验证能力、失败条件和代表论文。命名相似不证明机制相同，命名不同也不证明创新。

发展阶段依据新问题、新机制、新评价与研究重心变化归纳。若证据呈现并行路线而非阶段替换，报告并行结构，不机械按年份编造历史。

### 7.3 痛点与覆盖

PainPoint 必须包含现象、条件、影响、证据和范围。ResidualGap 表示已有方法在具体条件上的剩余缺口。

覆盖矩阵状态：`directly_addressed/partially_addressed/observed_improvement/observed_failure/not_evaluated/not_applicable/conflicting_evidence/unknown`。不得把 `not_evaluated` 自动升级为 `unsolved`。

评价缺口可支持“评估协议+方法”的故事，但它并不证明已有方法能力差。

### 7.4 ResearchOpportunity

必要内容：问题与价值、现有方案、已解决部分、剩余条件、证据类型、根因假设、反例、替代解释、方法空间、拥挤方案、数据等级、最低验证和风险。

机会类型包括能力、评价、机制、数据/监督和泛化/部署。每个机会经过以下检查：问题可信或可快速验证、价值具体、现有覆盖不足、有方法空间、可測量、有初步差异、资源需求可陈述。

不把“任何直接迁移都无价值”当作通用结论。本项目偏好明确方法贡献；迁移方案须证明新增问题或约束的意义和必要改造，不能只靠换数据命名。

### 7.5 评分与 G3

分别报告价值、证据、持续性、机制清晰度、方法空间、可测量性、数据可行性、投稿适配、撞车风险及故事一致性。总分只辅助排序，不掩盖致命风险，也不预测录用概率。

目标展示 5–12 个机会，用户选 1–3 个。没有足够合格机会时只报告真实数量及阻塞原因。每个机会必须展示最强已找到反证，或明确反证搜索范围与未找到状态。

## 8. 设计七：跨领域机制迁移与 Idea 生成

### 8.1 从问题机制包出发

输入是已确认机会、支持/反对证据、现有边界、根因、条件和约束，不是“找一个最新模块”。先抽象医学现象为任务问题、信息流问题和领域无关结构。

ProblemSignature 描述信号占比、语义价值、频率、样本稀有度、监督、失败过程、所需性质和目标约束。初始根因保持假设状态，不能为了搜索方便升级为事实。

### 8.2 来源与查询

依次探索同模型不同应用、不同视觉任务相似机制、跨模态相似结构。来源可包括自然图像、视频、小目标、长尾、编辑、多模态、LLM、强化学习等，但不要求每个 Idea 必须跨领域。

先桥接搜索确认源领域存在相似问题，再检索解决机制。源论文分线索级与核心精读级；Idea 的关键迁移依据必须全文核验或明确受限。

### 8.3 TransferCard 和同构检查

TransferCard 必含源问题、源机制、证据、不变原理、目标问题、对象/过程对应、源领域依赖、目标不匹配、必要改造、预期收益、失败风险和验证。

检查对象是否相似、失败过程是否相似、源约束是否可用、改造是否必要、改造是否解决真实目标需求。视频时间轴与独立二维医学图像不自动同构；把时间替换成 timestep 只是假设，需要机制论证。

### 8.4 先机制后实现

机制设计先说明改变什么信息流、为何可能有效，再提出实现变体。相同根因和机制下的 token memory、特征缓存或一致性损失可能属于一个故事的不同实现，不能凑成多个 Idea。

每个机会先形成约 8–20 个 Seed，聚类合并后得到约 5–10 个完整候选。可保留稳健型、机制型、探索型；不为类别配额捏造方案。

### 8.5 IdeaProposal 契约

必要字段：目标机会、具体问题、证据基础、根因和替代解释、洞察、迁移依据或本领域机制、方法信息流、必要/可选组件、医学改造、最简版本、预期贡献、可检验预测、反证结果、Probe、强简单基线、完整实验需求、数据等级、计算估计、已知最近工作和风险。

每个核心组件回答：针对哪个失败；删掉后预期什么变化；怎样通过消融区分；更简单替代是什么。

替换 backbone、添加注意力或损失本身不构成故事。不能仅凭组件常见就机械否决，判断依据是是否有实质机制、重要约束与可验证增益。

### 8.6 Mechanism Probe

先设计最低成本诊断，区分根因与竞争性解释，再考虑复杂方法。Probe 未执行时只能输出计划。根因未获支持时允许收缩、重构或淘汰，禁止隐藏简单解释来挽救叙事。

假想例：小病灶信息弱化可能由样本稀少、编码器压缩、条件噪声、全局目标或指标不稳定造成。需要控制这些因素，而不是先认定某一个原因。

## 9. 设计八：撞车检查、对抗式审稿与故事筛选

### 9.1 新颖性分解

分别核查问题定义、根因解释、方法机制、实现、医学改造、任务、评价和数据。源机制已存在但目标约束不同，可能仍有贡献空间；不得用“首次医学应用”替代必要性的证明。

新颖性状态：`unsupported/likely_existing/partially_distinct/materially_distinct/uncertain`。对计划中未实施方法的判断均为待验证的新颖性评估。

### 9.2 两级检索

所有候选做快速筛查；对幸存者做全文级 Prior-art Review。沿问题、根因、机制、任务/模态、评价/数据五轴检索，也搜索同义术语和不同命名。

必须独立检查本地快照之后的公开工作、arXiv、OpenReview、官方论文页和项目代码线索。保存查询、来源、检索日期、首次公开时间及版本。首次公开日期不可靠则标记不确定，不能从最终出版年推断优先权。

### 9.3 最近工作矩阵

每个重点故事目标比较 3–10 篇最危险工作，列出问题、假设、机制、监督、医学约束、评价、重合和实质差异。数量不足时说明，不用弱相关论文凑数。

尚未做实验时，不以“我们的结果更好”作为差异。关键最近工作全文缺失时，方法重合判断保留 `uncertain`。

### 9.4 判断与修订

- `survive`：未发现已知近乎相同工作，至少存在可解释的重要实质差异，且能设计决定性比较。
- `revise`：问题、机制、监督、范围、评价或贡献边界需要结构性变化。
- `reject`：主要主张高度重合，或差异仅靠改名、忽略文献、换数据和无依据包装。

每个 Idea 最多两轮修订。修改标题不算一轮有效机制修订。需要隐藏同期工作才能成立的故事淘汰。

默认不生成绝对“世界首次”“尚无人研究”。表述必须带检索时间、来源范围和盲点。没有搜到不证明不存在。

### 9.5 审稿镜头

从问题价值、技术差异、证据、实验、医学合理性、泛化/复现、伦理/隐私/许可审查。模拟评审只是风险诊断，不是实际会议决定或真实专家意见。

每个故事生成最强一句话拒稿攻击、严重度、当前防守、所需证据和决定性实验。没有找到致命缺陷可以如实记录，不能强制制造一个假缺陷。

### 9.6 简单基线与实验审计

针对故事选择重采样、类别平衡、局部 crop、区域损失、高分辨率、更好编码器、普通条件控制、匹配参数、更长训练或后处理等有力替代。

Experiment Auditor 建立 Claim–Experiment Matrix，检查主张是否由指标和对照真正检验。声称局部病灶保真度却只有全局 FID 属于证据计划不匹配，不等于已有方法已被证明失败。

### 9.7 G4 与风险分层

目标保留 3–5 个重点故事，采用多维评分和 Pareto 比较呈现稳健、机制和探索路线。若只有 1 个或 0 个合格候选，应直接说明，不降低门槛保证输出数量。

用户选择主故事和备选；状态为 `selected_for_validation`，不是 `validated_contribution`。切换条件包括 Probe 否定、简单基线等效、重要新撞车和数据不可得。

## 10. 设计九：最终故事、实验闭环与论文骨架

### 10.1 Research Story Package

```text
story/
├── story_manifest.yaml
├── narrative/       # 一句话故事、Story Spine、完整叙事、贡献边界
├── method/          # 方法规范、信息流、组件理由、实现变体
├── experiments/     # Probe、最低验证、完整实验、矩阵、基线、指标、停止条件
├── review/          # 最近工作、攻击与防守、过度主张边界
├── paper/           # 标题、摘要逻辑、各节提纲
└── reports/research_story_package.md
```

Markdown 为阅读视图，结构化对象为权威内容。图示规范可作为产物，但不意味着首版自动生成全部方法图。

### 10.2 Story Spine 与 Method Spec

主线必须贯通：医学场景 → 证据限定的问题 → 现有方案 → 剩余条件 → 根因假设 → 机制洞察 → 方法信息流 → 医学改造 → 可检验预测 → 贡献边界。

Method Spec 说明输入/条件/输出、基础模型、信息来源与去向、更新阶段、训练目标、推理步骤、条件缺失/噪声行为、兼容范围、复杂度估计、组件必要性与替代实现。

Level 0 是诊断；Level 1 是最简核心机制；Level 2 只在前者得到支持后增加必要适配。不能为了论文结构预先要求三个模块。

### 10.3 E0/E1/E2

- E0：机制诊断，检验根因并区分替代解释。
- E1：最低可行方法，标准数据和 backbone、关键指标、强简单基线、最小消融。
- E2：完整论文证据，按主张需要增加数据、近期强方法、统计、泛化、压力测试、下游/专家评价、隐私和效率。

这些是实验计划与结果解释节点，不是首版自动训练功能。系统仅在用户导入可核验运行记录后标记相应实验执行状态。

### 10.4 Claim–Experiment Matrix

每个主要 Claim 绑定测量对象、主要指标、决定性对照、支持条件、否定条件、资源和剩余不确定性。数值门槛在查看正式测试结果之前确定，并与实际数据分布、样本量和研究问题匹配，不提前编造“显著提升”的幅度。

诊断、相关性和干预实验的证据强度要区分；去掉一个模块不自动证明完整因果机制。

### 10.5 医学图像生成评价

指标按主张选择，不堆通用列表：全局分布、局部结构/病灶、条件一致性、多样性、下游任务、临床语义、隐私和效率分别承担不同证据角色。

无配对合成不得默认使用逐像素 PSNR/SSIM 作为保真度依据；有配对任务也必须说明对齐和对应关系。合成样本的病灶检测器可能有偏差，需要人工或独立评价交叉核查。下游提升不自动等于临床部署安全或获益。

患者级划分、生成训练集与最终测试隔离、评价编码器数据来源、合成数据量/比例、条件信息、参数量和训练预算均须审计。CT/MRI 独立切片仍按患者防泄漏。

### 10.6 消融、压力测试与停止

消融围绕信息流角色设计：定位机制、注入阶段、条件噪声、随机区域、匹配参数、简单替代。压力测试针对故事边界，不能预设所有模态和病灶都有效。

预先区分 primary/secondary/exploratory metrics，写 Go/Revise/Stop 规则。试验未支持主要假设时，不以事后换指标冒充验证；新发现使用 `post_hoc_origin` 和新版本。

### 10.7 实验结果回流

结果清单包含 experiment ID、协议版本、代码 commit、数据版本、划分、随机种子、配置、指标、输出文件哈希及关联 Claim。仅上传一张表时标记来源未完全核验，不宣称可复现。

结果归类为内部实验依据。系统更新矩阵、标记支持/矛盾、重新审稿，并选择证据增强、主张收缩、机制重构或停止。不能把一次内部结果升级为普适事实。

### 10.8 论文骨架

输出标题备选、摘要逻辑、Introduction 问题链、按机制组织的 Related Work、方法信息流、按 Claim 排列的实验、局限和未解风险。

实验前不写虚构数字或已完成时态。标题中的 robust、generalizable、clinically reliable 等词须满足对应证据条件。论文骨架可以提前生成；正式结果主张须经实验与研究者核验。

## 11. 设计十：运行时、API/CLI/Skill、治理与评测

### 11.1 单向依赖

```text
Skill / CLI / 未来界面
        ↓
ResearchAgent Python API
        ↓
Orchestrator + State/Gate/Task 管理
        ↓
研究阶段服务
        ↓
Corpus / Search / Fulltext / Parser / Embedding / LLM / Storage Adapters
```

Skill 与 CLI 不绕过 API 直接改状态。专业角色不决定 Gate、不写 corpus、不删除其他角色输出。核心包通过文件系统写入范围和接口限制实现只读边界，而不是只写一句 Prompt。

### 11.2 有效配置

系统默认 → 领域配置 → Workspace 覆盖。G1 冻结研究范围与快照。Prompt、模型、解析器、索引和工作流版本进入执行配置锁；执行设置可版本化更新，但不得借更换模型静默改变研究边界。

密钥放环境或本地秘密配置，不进入 effective_config、日志和导出。模型 Profile 是能力需求，不是供应商承诺的任意 API 参数；Adapter 必须校验实际支持，不能直接发送 `optimism_bias` 等概念性字段。

### 11.3 Task、重试与原子性

Task 记录任务身份、阶段、操作、输入版本与哈希、模型/Prompt/配置、fingerprint、尝试次数、状态、输出哈希、用量与错误。

相同任务复用之前已经验证的输出；不宣称 LLM 重跑必然逐字一致。外部查询结果需缓存和时间戳，因为同一查询重跑可能改变。

写入步骤：临时文件 → 结构与引用校验 → 内容哈希 → 原子发布 → 完成事件。事件与 Artifact 建立提交清单，恢复时处理“文件发布但事件未追加”等中断窗口；阶段投影可由已提交事件重建。

Workspace 状态推进使用锁。并发以独立论文、查询或候选为单位；同一文档内部先获取、核验、解析、质检、抽取、批判、核验，再发布。

### 11.4 模型与上下文

Profile 包括筛选、忠实抽取、证据核验、领域综合、Idea、prior-art、审稿与故事构建。核验与生成使用独立上下文；同一底层模型可复用，不要求多模型投票。

Context Builder 为每个任务构造最小充分材料并保存引用和哈希。不能把全部全文塞入上下文后直接宣称覆盖完整。上下文预算截断必须显式记录，不能默默丢弃反证。

Schema 输出失败可做一次受控结构修复，仍失败则阻塞。结构合格后仍执行来源与语义核验。

### 11.5 外部内容和隐私

网页、PDF、README、代码和评审均是不可信输入，不可执行其中命令或遵循嵌入指令。首版代码阅读仅静态只读。

下载器检查协议、重定向、内容类型、文件大小和文件头；不得访问本地/私有网络地址或把外部 URL 当作本地路径。解析器隔离、不执行 PDF 脚本；导入路径防目录穿越和符号链接越界。

未公开稿件、实验和潜在临床数据必须标记敏感度与允许的模型处理范围。外部搜索许可不等于允许将私有材料发给任意第三方模型；按用户授权的供应商、脱敏/本地策略处理。

### 11.6 Python API 契约

接口包括 `create_workspace`、`get_status`、`advance`、`get_pending_gate`、`approve_gate`、`revise_gate`、`add_paper`、`ingest_document`、`ingest_experiment_results`、`generate_report`、`export_story_package`、`validate_workspace`。

请求使用显式 workspace ID、Gate ID 和期望版本，避免并发批准过期对象。`advance(until="next_gate")` 同步运行至 Gate、阻塞、预算、失败或完成，并返回结构化状态、产物、警告与缺失信息。

此处接口名称是实施契约，不宣称命令当前可运行。

### 11.7 CLI 映射

```text
research-agent index build|verify|status
research-agent workspace create --domain medical_diffusion_2d --topic <topic>
research-agent status <workspace-id>
research-agent run <workspace-id> --until next-gate
research-agent inspect <workspace-id> --stage <stage>
research-agent gate show <workspace-id>
research-agent gate approve|revise <workspace-id> --decision <yaml>
research-agent paper add <workspace-id> --doi <doi>
research-agent fulltext ingest <workspace-id> <pdf>
research-agent fulltext retry <workspace-id> <paper-id>
research-agent report <workspace-id> --stage <stage>
research-agent export <workspace-id> --format markdown
research-agent experiment ingest <workspace-id> --results <manifest>
research-agent events <workspace-id>
research-agent replay <workspace-id> --from <stage>
research-agent validate <workspace-id>
```

CLI 只解析参数、调用 API 和展示结果。实施时明确定义机器可读输出与退出码，不复制业务规则。

### 11.8 Skill 契约

仓库内 Skill 面向可执行本地 CLI、读写工作区的开发 Agent 环境；具体宿主安装路径与命令能力在实施时验证，不承诺所有聊天界面都能直接运行本地引擎。

Skill 负责理解用户、查找课题、调用 API/CLI、展示阶段结果、收集四个 Gate、写 DecisionRecord 和展示故事。每次先读取 Workspace，不猜测对话记忆。

只有当前宿主不具备所需执行或读取能力时明确说明缺项，不模拟执行。Skill 不携带唯一业务状态、算法或不可复用的提示长链。

### 11.9 预算、审计与导出

RunManifest 记录输入输出版本、来源与日期、模型/Prompt/解析器、调用次数、用量、缓存、重试、错误和阶段状态。成本估计须带计价来源日期或标记未知。

运行预算包括搜索轮次、全文篇数、外部结果、模型调用、修复次数、撞车修订和可选费用上限。用尽后提供部分结果和未覆盖范围。

默认不提交 indexes、workspaces、cache、原始 PDF、密钥和私有材料。导出采用白名单，仅包含允许分享的元数据、来源定位、必要短片段、Agent 结论与设计；自动排除全文和敏感实验。不得假设 `.gitignore` 能替代权限、删除已跟踪文件或保护外部调用。

### 11.10 评测

工程测试：快照哈希、索引来源、只读 corpus、Schema、Gate 版本、依赖失效、原子写入、崩溃恢复、并发、幂等、导出边界和提示注入。

检索黄金集：关键论文、3D/2.5D、重建主线、独立 CT/MRI 切片、困难负例、评价论文和最新竞争者。初始目标 Recall@100 ≥90%、范围分类 F1 ≥90%、主任务分类 F1 ≥90%、核心明显重复率 ≤10%；必须报告标注数、抽样方法、不确定性和失败案例。这些是拟定验收阈值，不是已达到的成绩。

证据评测：Locator、身份错配、支持关系、遗漏/失败混淆、摘要越权、作者主张提升和反证忽略。对最终交付物要求已知违规为零且所有主要 Claim 可追溯；“抽查零错误”不等于保证模型永久零语义错误。

科研效用：与普通标题摘要检索+单次 Idea 生成比较，尽量匹配模型、可访问资料与预算，并用消融区分全文、反证和对抗流程的增益。研究者盲评覆盖、真实性、机制、迁移、近似工作识别、可实验性和决策价值。

时间截断回测：检索库截断不等于模型知识截断。模型可能已见未来论文；必须记录模型训练信息可知范围、禁用未来搜索、标记潜在记忆污染。结果只作为受污染风险约束的回顾性诊断，不声称证明新发现或预测能力；更可靠的补充是前瞻性盲评与未公开测试课题。

## 12. 首版里程碑与验收

### 12.1 纵向切片实施

| 里程碑 | 交付 | 验收核心 |
|---|---|---|
| M1 基础骨架 | Python 包、Schema、Workspace、Task、事件、Gate、CLI、corpus adapter | 只读快照、非法转换阻止、崩溃恢复、旧 corpus 测试不变 |
| M2 检索至 G2 | SQLite/FTS、一个向量实现、查询、筛选、覆盖与候选报告 | 真实快照索引、范围回归、排除理由、用户确认 |
| M3 精读至 G3 | Resolver、上传、一个主解析路径、两遍阅读、证据、领域和机会 | 真实全文定位、降级诚实、局限分离、机会依据 |
| M4 Idea 至 G4 | 迁移卡、Seed/Idea、最新撞车、审稿、实验审计 | 非同质候选、最近工作、简单基线、明确风险 |
| M5 故事与 Skill | Story Package、实验蓝图、论文骨架、Skill、端到端评测 | 四 Gate、恢复、选择记录、无虚构实验 |

每个里程碑使用同一个真实研究 Workspace。可用小型 fixture 测试控制流，但不得把 mock 数据跑通称为真实科研端到端验收。

### 12.2 首版最小基础设施

仅需一个 corpus adapter、一个 SQLite/FTS 实现、一个本地向量实现、一个主要 LLM adapter、一个外部搜索 adapter、一个全文解析主路径、用户补充路径、一个本地 Artifact Store、一套领域配置、CLI 和 Skill。

实施计划再选择和锁定具体模型服务、embedding、解析器、Python 依赖与版本，并验证其授权、能力、成本和测试替代。对未验证的外部能力不能以“接口已定义”冒充已集成。

### 12.3 端到端验收清单

- 指定 corpus snapshot 校验与索引构建成功，原始 corpus 未被修改。
- 创建、暂停、恢复和回退同一 Workspace，四个 Gate 不可绕过。
- 候选、全文、机会和故事提供来源、选择原因、认知状态与缺失说明。
- 实际执行合法全文获取或用户导入，完成关键证据定位。
- 建立方法谱系和条件化痛点，不以未检索到证明空白。
- 候选 Idea 有机制、替代解释、Probe、强简单基线和反证结果。
- 实际执行外部最新工作核查，保存范围、日期和最近工作比较。
- 用户选择后生成主故事、可选备选、Method Spec、E0/E1/E2、实验矩阵、贡献边界和论文骨架。
- 无虚构论文、全文读取状态、实验结果或录用概率。
- 工程与质量评测分别报告，不以结构测试代替科研效用。

论文、机会和故事的数量区间是充分覆盖时的目标，不是通过验收必须填充的内容。若质量门控淘汰全部候选，系统应正确返回“当前未找到合格故事”及阻塞证据；这是控制流正确的结果，但不算首个成功研究故事的效用示范。

## 13. 整合自审与消歧

以下条款用于使已批准设计一致，不扩大产品范围：

1. 保留十部分核心方案及 D01–D20 决策，不再追加产品形态选择题。
2. 维度按单样本输入而非数据来源判断；原始三维数据切片不等于 3D 模型。
3. 全文缺失和评价遗漏不同；保留不可获取的危险最近工作以避免可访问性偏差。
4. FACT 表示范围明确的可定位陈述；作者声称不是独立验证。
5. Schema 保证结构与来源完整性，不机械保证语义或科学正确性。
6. 数量是目标，不能为了 5–10 个 Idea 或 3–5 个故事降低新颖性和证据门槛。
7. 示例科研机制均为假想；不以说明案例替代本课题实际调研。
8. MICCAI rubric 和评测阈值是项目设计，不冒充官方评分或已完成实验。
9. 模型 Profile 字段表达要求，由 Adapter 映射已支持参数，不发送虚构 API 设置。
10. 缓存实现可重放，不承诺随机模型重跑逐字一致；外部来源另有版本与时间。
11. 历史截断回测标记基础模型潜在未来知识污染。
12. 实验规划与实验执行分离；E0/E1/E2 状态由真实结果输入推进。
13. 新证据与用户修改通过版本和依赖失效处理，不静默覆盖已有批准。
14. 当前提交只新增设计文档；README 修正、`.gitignore`、Python 配置和源码修改属于后续实施任务。

## 14. 审阅与实施交接

十部分设计已经在对话中逐项获得同意。本文件将其整合为同一规范，等待研究者对成稿审阅；不把设计批准解释为已经完成实现或真实文献研究。

成稿确认后编写独立实施计划，逐任务明确文件路径、测试用例、验收命令、依赖和检查点。优先 M1，再沿真实端到端路径推进，不一次性创建庞大空框架。

任何改变研究主线、二维限制、Gate、事实/假设分离、方法贡献或只读 corpus 边界的决定，都要新增决策记录。替换可插拔技术实现若不改变这些契约，可在实施计划中记录，不需重做全部产品决策。

最终系统应让研究者看清：证据支持到哪里，假设从哪里开始，最近工作已经做了什么，真正的新差异在哪里，哪个实验最先决定继续或停止，以及如何把验证结果组织成可信的论文故事。
